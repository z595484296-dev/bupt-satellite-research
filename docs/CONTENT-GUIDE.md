# 内容维护指南

## 登录与账号

打开当前网站地址后的 `/admin`。首次账号为 `admin`，初始密码请在本机 `.runtime/admin-credentials.txt` 中查看，勿将其复制进公开页面。登录后进入“账号安全”修改密码，新密码长度为 12–200 个字符。修改后会退出所有已登录会话，需使用新密码重新登录。

Apple 风格本机对比版沿用复制时的原版账号密码，没有重复保存明文初始凭据。两个版本的后续修改与合作意向独立保存；原版历史留言没有搬入本对比版。新装源码包则按首次启动流程生成账号。

重启服务不会重置密码。`.runtime/admin-credentials.txt` 记录的是初始密码，改密后不会更新它；确认新密码已妥善保存后，可自行清理这份初始凭据文件。

## 新增、修改与下架

1. 在“内容库”点击“新建内容”，选择“研究成果”“观点文章”或“中心动态”。
2. 填写标题、分类、摘要和正文。发布日期使用 `YYYY-MM-DD` 或 `YYYY-MM`，也可留空。研究成果可填写成果形式，文章和动态可填写发布渠道。来源链接需要完整的 HTTPS 地址。
3. 按需上传封面图片和 PDF 附件，勾选“首页 / 列表推荐”参与相应推荐展示。
4. 点击“保存草稿”，内容仅在后台内容库中显示。再次打开可继续编辑，并展开“预览正文排版”核对。
5. 确认后点击“保存并发布”，内容出现在公开网站；已发布内容修改后也需点击该按钮生效。
6. 如需下架，打开已发布内容，点击“转为草稿（下架）”。正文和文件关联会保留，方便修改后再发布。

后台新建内容时默认是草稿。保存草稿会让已发布内容下架，当前版本没有独立的“线上旧版 + 未发布修订版”。离开编辑页面前请保存。

如果提示“内容已被更新”，说明其他页面已保存过内容。点击“获取最新版本”，核对当前编辑内容后再保存，避免覆盖别人刚做的修改。后台目前共用一个管理员账号，没有成员权限分级。

## 首页展示与方向关联

首页从已发布内容中显示研究、观点和动态，未发布草稿不参与展示。方向面板展示最多两条相关内容，研究优先，其次按推荐标记与日期排序。上传的真实封面会替换对应研究卡片的地球视觉。新增、编辑或下架后，可在前台检查实际展示。

首页研究方向可点击切换，也支持左右方向键、Home 和 End 键选择。方向的名称和说明在“站点信息”中维护。选择方向后，说明、研究卡片和相关观点会一起更新；没有匹配内容时显示说明及合作入口，不沿用其他方向的卡片。

默认四个方向使用同义关键词（如产业政策匹配“政策研究”“政策分析”），匹配内容的标题、分类、副标题和摘要，不包含中心动态。自定义方向名称按“与、和、及”等分隔词提取关键词。

这是一种自动关键词关联，当前后台没有为每篇内容手动指定研究方向的精准标签。修改方向名称或文章文案可能改变关联结果；应按真实内容填写，不必为匹配堆砌关键词。后台可持续新增内容和上传文件；若以后需要人工编排方向关联，可在现有结构上增加专门的标签或关联字段。

## 文章阅读与研究详情

观点有正文时，在本站展示全文；没有正文而有原文链接时，从列表直接在新窗口打开原文。请填写文章的独立公开详情链接，避免填写公开空间首页。只有空间首页的旧记录会明确标为“前往公开空间”。仅有 PDF 的观点可直接打开 PDF 阅读。

研究详情展示正文、成果形式、分类和已填写的作者、日期、PDF，不会自动生成研究结论或进度。延伸阅读根据研究所属方向匹配已发布内容。中心动态按日期归入年度，新增后自动排序，不需要手动调整页面。

从研究详情或方向面板进入合作页，会带入可编辑的交流主题。姓名、邮箱等联系人信息仍由访客自行填写，提交后仅管理员可读取。

## 正文格式

正文支持普通段落、二级标题和无序列表。段落或不同格式的块之间留一个空行：

```text
这是一段介绍文字。

## 研究议题

这里填写该议题的具体说明。

- 第一个要点
- 第二个要点
```

目前不解析任意 HTML、Markdown 表格或行内图片语法。标题、摘要、正文和 PDF 分开维护；上传 PDF 不会自动提取成正文。已有公开空间的文章可先保留来源链接，获得完整文本后再补充正文。

## 上传图片和 PDF

“封面图片”支持 PNG、JPEG、WebP；“PDF 附件”支持 PDF。每次上传一个文件，单文件最大 10 MB。上传完成后仍需保存或发布内容，才能保留该条内容的文件关联。

“替换文件”生成新的文件地址；“移除关联”只取消当前内容引用，不删除磁盘文件，便于保留历史内容。草稿不会出现在公开列表中，但上传媒体使用可访问的公开地址，因此此处仅上传计划对外展示的材料。

## 修改站点信息

“站点信息”可编辑首页主标题和副标题、中心主张、简介摘要、完整简介、页脚文案及公开联系邮箱。邮箱可留空，留空时页面不显示邮箱链接。四个研究方向的名称及说明均可修改，当前布局固定保留四项。

修改后点击“保存站点信息”。主体名称、学校归属和整体导航结构属于网站配置；若后续需要新增栏目或改变主体，应修改对应代码与种子结构，而不是将信息塞进正文。

## 查看合作意向

访客在“合作交流”页提交的姓名、单位、邮箱、方向和需求保存在后台“合作意向”中，仅管理员可读取。可标记为“待处理”“已查看”“已跟进”，并点击“刷新”获取新留言。

提交成功表示服务器已保存留言。当前版本不自动发送通知邮件，也不代替管理员回复；需要通过留言中的联系方式自行跟进。

## 备份

内容每次保存或修改站点信息前，服务器会将上一版 `content.json` 保存到 `data/backups/`。后台“导出内容备份”也只下载当前内容及站点设置，**不包含上传文件、合作留言或账号**。自动快照不等同于完整灾备，当前没有自动清理快照的策略。

完整备份应复制实际 `DATA_DIR` 下的所有文件，包括 `content.json`、`uploads/`、`inquiries.json`、`admin.json` 和 `backups/`。

在本机默认目录下，可以先用 `Ctrl+C` 停止唯一运行的 Node 服务，再从项目目录执行：

```powershell
$projectDir = (Get-Location).Path
$activeData = Join-Path $projectDir 'data'
$backupRoot = Join-Path $env:USERPROFILE 'Documents\satellite-center-backups'
$backupPath = Join-Path $backupRoot ('data-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
Copy-Item -LiteralPath $activeData -Destination $backupPath -Recurse
```

若服务设置了 `DATA_DIR`，将 `$activeData` 改为那个实际绝对路径。复制结束后，核对备份中的内容文件、上传目录和留言文件均存在，再启动服务。备份包含私人留言和账号摘要，应放在受控位置；不要提交到代码仓库或公开网盘。

## 从完整备份恢复

先停止唯一运行的服务。保留当前数据目录，将选定的完整备份复制到一个新目录，再切换 `DATA_DIR`，这样可以保留回退路径：

```powershell
$projectDir = (Get-Location).Path
$chosenBackup = 'C:\填写完整备份目录的绝对路径'
if (-not (Test-Path -LiteralPath (Join-Path $chosenBackup 'content.json'))) {
    throw '没有找到完整备份中的 content.json，请检查备份路径。'
}
$restoreDir = Join-Path $projectDir ('data-restored-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
Copy-Item -LiteralPath $chosenBackup -Destination $restoreDir -Recurse
$env:DATA_DIR = $restoreDir
npm.cmd start
```

启动生产版本前应已有 `npm.cmd run build` 的输出；开发时也可运行 `npm.cmd run dev`。恢复后核对公开内容、上传图片/PDF、草稿和合作留言，再继续维护。恢复 `admin.json` 后，应使用该备份对应时期的管理员密码登录。

上述 `$env:DATA_DIR` 只影响当前 PowerShell 会话。确认恢复成功后，要将新目录写入实际启动服务的环境配置，后续重启才会继续使用它；不要同时启动两个进程写入这些文件。若需要回退，停止服务并将 `DATA_DIR` 指回原数据目录即可。
